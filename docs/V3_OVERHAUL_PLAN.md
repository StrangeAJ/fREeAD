## 1. Current state and root causes (from the survey)

**Stack:** Flutter 3.32.8 / Dart 3.8, Provider, sqflite (DB v6), dio, `html` package, flutter_html (unused by the live screen), share_plus, url_launcher, file_picker, flutter_secure_storage. Android only in practice. App id `com.example.freead` (keep - changing it breaks upgrades on installed devices). Release signed with debug key (keep - sideload app).

**Wired screens today:** `main.dart` -> `AppInitializer` -> `HomeScreen` (4 tabs: Home, "Feeds" (CategoriesTab), Saved, Settings) -> `ArticleReadingScreen` (`lib/screens/article_reading_screen.dart`). `FeedManagementScreen`, `CategoryArticlesScreen`, `FeedArticlesScreen`, `FuturisticSearchDelegate`, `FeedSummaryDialog`.

**Dead code (delete):** `lib/screens/article_reading_screen_enhanced.dart`, `lib/screens/specialized_article_screens.dart` (35 analyzer errors - references non-existent params), `lib/screens/test_import.dart`, `lib/screens/full_article_test_screen.dart`, `lib/services/on_device_ai_service.dart` (+ `gemini_nano_android` dep, unused), `lib/services/html_to_markdown_converter.dart` (unused), `tests/manual/*` (does not compile), `summarization_service_brace_fix.patch`, `flutter_log.txt`.

**Confirmed bugs (P0):**
1. **Extractor is silently broken.** `EnhancedArticleService._grabArticle` calls `element.querySelectorAll(':scope > div')`; the Dart `html` package throws `UnimplementedError: ':scope' selector`. `processHtml` catches it and returns `null`, so the whole readability path fails for every site that lacks JSON-LD `articleBody`/microdata/site-specific selectors. 6 of the unit tests in `test/enhanced_article_service_test.dart` fail for exactly this reason. This is why "v1 worked, v2 doesn't".
2. **Reader destroys formatting.** `ArticleReadingScreen._cleanContent` strips all tags with a regex and collapses all whitespace, so full articles render as one giant paragraph with no headings, images, lists or links.
3. **RSS dates are wrong.** `RssService._parseDate` only calls `DateTime.parse`; RFC-822 `pubDate` (used by nearly every RSS 2.0 feed) fails, so every article gets `DateTime.now()`. Sorting/grouping is meaningless.
4. **Adding a feed does nothing useful.** `FeedProvider.addFeed` inserts a row titled "Loading..." with an empty description and never fetches feed info or articles. Title stays "Loading..." forever.
5. **Feeds tab opens empty lists.** `CategoriesTab` passes `feed.id` as a *category id* to `CategoryArticlesScreen`, which queries `articles.categoryId = ?`. `Article.categoryId` is never set, so the list is always empty.
6. `FeedProvider._categories` is never loaded; categories exist in the DB but are unreachable from the UI.
7. `RssService.fetchFeedInfo` assumes RSS 2.0 (`channel`) and crashes on Atom; no User-Agent header (many hosts return 403/429 - see screenshot in `Screenshots/`); no charset handling; RSS `content:encoded` HTML is stripped to plain text at parse time (loses images/formatting that many feeds ship in full).
8. Theme references fonts `Inter`/`Georgia` that are not bundled -> falls back to Roboto. Light theme is half-defined (no chip/input/list themes) so light mode looks different from dark.
9. Misc: About screen hardcodes "2.0.0" while pubspec says 1.0.0; Android label is lowercase `freead`; card share button is a no-op; many settings are loaded but have no UI or effect (auto refresh, cleanup days, etc.); `print` everywhere.

**Baseline:** `flutter analyze` = 293 issues (35 errors, all in dead code + `tests/manual`). `flutter test` = 32 passed, 6 failed (all the `:scope` bug), 2 skipped.

## 2. Product decisions

### 2.1 Design language: "quiet instrument" (futuristic, minimal)
- **Surfaces:** near-black cool background, layered elevated surfaces, 1px hairline borders instead of shadows, subtle accent glow only on the primary action. Optional pure-black (AMOLED) mode. Light mode gets the same structure with off-white surfaces.
- **One accent colour**, user-selectable: Emerald (default, brand continuity), Cyan, Violet, Amber, Rose, Mono. Optional Material You dynamic colour on Android 12+.
- **Typography:** Space Grotesk (display/headlines, tight tracking), Inter (UI/body), Literata (reading body, user can switch to Inter). All bundled in `assets/fonts/` (already downloaded).
- **Shape:** 12 (chips/buttons), 20 (cards), 28 (sheets/dialogs). Pill chips. Glass (blur) top bar and bottom bar.
- **Motion:** 200-300 ms `easeOutCubic`; fade-through page transitions; Hero on article images; skeleton shimmer while loading; nothing bouncy.
- **Consistency:** every screen uses the same `AppScaffold`/`GlassAppBar`, `SurfaceCard`, `SectionHeader`, `PillChip`, `EmptyState`, `AppSnackBar`, `AppBottomSheet` primitives from `lib/widgets/ui/`. No screen defines its own colours.

### 2.2 Extraction ("robust against most sites")
Three tiers, orchestrated by `ArticleExtractor` (engine setting: **Auto** (default) / Fast / Browser):
1. **HTTP + Dart Readability** - fast, works in an isolate: browser-like headers, redirects, charset detection, JSON-LD / microdata / site selectors / readability scoring (with the `:scope` bug fixed), lazy-image and srcset recovery, relative URL fixing, boilerplate removal, quality score.
2. **AMP fallback** - if the page links `rel="amphtml"`, extract from the AMP page (usually clean and JS-free).
3. **Headless WebView + Mozilla Readability.js** (`assets/js/Readability.js`, already downloaded) - for JS-rendered/SPAs and hosts that block plain HTTP. Uses `flutter_inappwebview` `HeadlessInAppWebView`. Runs on the main isolate; single-flight queue.

Also: RSS `content:encoded` is kept as **sanitized HTML** (not stripped), so feeds that ship full posts read perfectly without any fetch. The reader renders HTML natively (`flutter_widget_from_html_core`), with highlights injected as `<mark>` elements.

### 2.3 Ask AI about article
Full-height draggable sheet with streaming chat (SSE) over the article text; suggested prompts; "ask about selection" from the text-selection toolbar; conversation persisted per article (DB table `article_chats`). Summaries reuse the same `AiService`. Providers: OpenAI, Claude, Gemini, OpenRouter, Perplexity, NVIDIA NIM, Ollama - all with per-provider model settings.

### 2.4 Auto-categorize feed providers
- **Quick (offline):** keyword + known-domain heuristics on feed title/description/URL. Runs automatically on add feed and OPML import.
- **AI:** one batched prompt returning strict JSON `{feedId -> category}`; may propose new categories. Preview screen with per-feed dropdown before applying.
- Categories become real: loaded, CRUD, grouped Feeds tab, category chips on Home, `article.categoryId` kept in sync with its feed.

### 2.5 Additional features (necessary)
- Feed discovery from any site URL (`<link rel=alternate>` + common paths), feed preview before adding, favicons.
- Parallel feed refresh (4 at a time) with progress; per-feed error/last-fetched status; refresh on launch when stale (interval setting).
- Article list styles: Card / List / Compact. Swipe actions (read, save). Long-press menu. Date group headers. Unread counts.
- Mark all read (all / feed / category). Article retention cleanup (keeps saved/starred).
- Prefetch full articles for offline reading (setting, capped).
- Reading: font family/size/line height, reading time, progress bar, remember scroll position, selection toolbar (Highlight / Note / Ask AI / Copy / Share).
- Starter packs on the empty state (curated working feeds by category).
- Working share on cards; consistent snackbars/dialogs/empty states; version from `package_info_plus`; proper app icon + dark splash.
- Search screen (replaces SearchDelegate) with filters.

Out of scope for v3 (note in README as future): background sync with WorkManager, notifications, text-to-speech, iOS polish, desktop.
